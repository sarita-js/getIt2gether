🔥 Firebase Setup

Connect a real backend in about 10 minutes. Free. No server needed.

What Firebase gives you

  • Real user accounts with secure email/password authentication
  • Tasks stored in the cloud — accessible from any device, any browser
  • Real-time sync — add a task on your phone, see it on your laptop instantly
  • Personality themes and notification settings persisted per user
  • Free Firebase Spark plan covers ~50,000 reads and 20,000 writes per day

1
Create a Firebase Project

  1. Go to console.firebase.google.com
  2. Click Add project
  3. Name it something like getit2gether
  4. Disable Google Analytics (not needed) → Create project

2
Register a Web App & Get Your Config

  1. Inside your project, click the </> Web icon to add a web app
  2. Give it a nickname (e.g. getit2gether-web) — don't enable Firebase Hosting
  3. Click Register app
  4. You'll see a firebaseConfig object. Copy all of it — you'll need it in Step 4.
What the config looks like:
{
  apiKey: "AIzaSy...",
  authDomain: "your-project.firebaseapp.com",
  projectId: "your-project",
  storageBucket: "your-project.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123:web:abc123"
}

3
Enable Authentication

  1. In the Firebase console sidebar, click Authentication → Get started
  2. Under Sign-in method, click Email/Password
  3. Toggle it to Enabled → Save
That's it for auth. Firebase handles password hashing, tokens, session persistence — everything.

4
Enable Firestore Database

  1. In the sidebar, click Firestore Database → Create database
  2. Choose Start in production mode (you'll set rules next)
  3. Pick a Cloud Firestore location close to your users → Enable

5
Set Firestore Security Rules Required

By default production mode blocks all reads and writes. Paste these rules so users can only access their own data:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Each user document and their tasks sub-collection
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;

      match /tasks/{taskId} {
        allow read, write: if request.auth != null && request.auth.uid == userId;
      }
    }
  }
}

To apply: In Firestore → Rules tab → paste the above → Publish.

What this does: A signed-in user can only read and write documents under /users/{their own UID}/. No user can see another user's tasks.

6
Paste Your Config into firebase-config.js

Open firebase-config.js in a text editor and replace the placeholder values with your actual config from Step 2:

const FIREBASE_CONFIG = {
  apiKey:            "AIzaSyYOUR_REAL_KEY_HERE",
  authDomain:        "your-project.firebaseapp.com",
  projectId:         "your-project",
  storageBucket:     "your-project.appspot.com",
  messagingSenderId: "123456789012",
  appId:             "1:123456789012:web:abcdef123456",
};
Save the file, then reload auth.html. The orange config warning should disappear.

7
Host It (So Any Device Can Access It) Recommended

Right now these are local files. To access your app from a phone or another computer, you need to host them. The easiest free options:

Option A — Firebase Hosting (recommended, free)

npm install -g firebase-tools
firebase login
firebase init hosting    # select your project, set public dir to "."
firebase deploy

Your app goes live at your-project.web.app — accessible from any device.

Option B — Netlify Drop (no CLI needed)

  1. Go to app.netlify.com/drop
  2. Drag your entire project folder onto the page
  3. Netlify gives you a public URL instantly
  4. Add your Netlify URL to Firebase → Authentication → Authorized domains
Important after deploying: Go to Firebase Console → Authentication → Settings → Authorized domains and add your deployed domain (e.g. your-project.web.app). Otherwise sign-in will be blocked.

🔧
Troubleshooting

Orange config warning still showing
Make sure you saved firebase-config.js and hard-refreshed the page (Ctrl+Shift+R / Cmd+Shift+R).
"auth/unauthorized-domain" error
Add your domain to Firebase → Authentication → Settings → Authorized domains. For local testing, localhost is already authorized.
Tasks not saving / "Missing or insufficient permissions"
Your Firestore security rules aren't set yet. Go to Step 5 and publish the rules.
Opening HTML files directly (file:// protocol)
Firebase auth works on localhost and deployed domains, but may block on raw file:// URLs. Use a local server: npx serve . or the VS Code Live Server extension.
